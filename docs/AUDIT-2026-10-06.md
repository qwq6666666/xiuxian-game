## 二、與 ChatGPT 共編留下的問題（按嚴重度）

### 高

1. **兩條 AI 分支都沒推到 origin，違反 AGENTS.md「做完一小段就推」。**
   `git ls-remote` 只有 `master`。`ai/chatgpt` 有 1 個未推 commit（`73a5618` 手機單列工具列），`ai/claude` 沒有獨有內容，只是落後 master 10 個 commit 的過期分支。機器壞了或資料夾被清掉，ChatGPT 那一筆就沒了。

2. **`ai/chatgpt` 比 master 落後 2 個 commit，缺少守門機制，且帶著舊檔。**
   - 分支裡沒有 `tests/architecture.test.ts` 與 `tests/save-shape.json`（master 的 `badec76` 才加）；與 master 的 diff 因此顯示「刪除」這兩個檔。
   - 分支裡仍追蹤 `live.html`（222 KB 的建置產物），master 已在 `badec76` 刪掉；worktree 資料夾裡也還在。若直接合併或誤採用分支版本，會把它帶回來。
   - `AGENTS.md` 少了「範圍由 CI 檢查」與「架構規則由測試守住」兩條。ChatGPT 讀到的是舊版規則。
   - 合併前必須先 `git rebase origin/master`（AGENTS.md 已寫，但沒做）。

3. **M24 當時越過了後來才訂的分工，且缺少 `[scope-ok]` 紀錄。**
   `8db9e41`（M24）改了 `src/core/`（`territory.ts` 新增、`travel.ts`、`world.ts`、`events.ts`）、`src/data/events.json`、`map.json`、`validate.ts`。現行 `check-scope.mjs` 明令 `ai/chatgpt` 不得動這些路徑。因為那個 commit 早於範圍檢查，沒被擋下，但：
   - 今天同樣的內容在 `ai/chatgpt` 上會讓 CI 失敗，而且沒有 `[scope-ok]` 可以引用。
   - M22（旅行）也動了 `core/save.ts`、`state.ts`、`travel.ts`，同樣情形。
   - 實際分工（ChatGPT 做了兩個含核心邏輯的里程碑）與文件寫的分工（ChatGPT 只做 UI 與文件）已經不一致。要嘛承認並更新規則，要嘛之後嚴守。
   - 好消息：M24 新增的兩個事件（`border_caravan_001`、`sect_vein_001`）沒有寫死參考名，sim 指標也維持 ✓。

4. **沒有作者區分。**全部 57 個 commit 的作者都是同一個人（`翰`），ChatGPT 的 commit 沒有 Co-Authored-By 或任何標記，無法用 `git log` 看出哪些是誰寫的，之後追責或回溯會很難。AGENTS.md 只規定了 Claude 要加 Co-Authored-By。

### 中

5. **行尾（EOL）仍是亂的：21 個檔案在版本庫裡是 CRLF 或混合。**
   `.gitattributes` 設了 `eol=lf`，但是之後才加的，舊 blob 沒有重新正規化。包含 `docs/GDD.md`（1037 行全是 CRLF）、`src/ui/render.ts`（946 行 CRLF）、`src/core/save.ts`、`state.ts`、`life.ts`、`review.ts`、`worldeffects.ts`、`data/validate.ts`、`types.ts`、`load.ts`、多個 JSON 與 `tests/talents.test.ts`。
   後果已經看得到：`ai/chatgpt` 的 `73a5618` diff 裡，許多「沒改內容」的行（如 `const codexEl = ...`）也顯示被改動，那是 CRLF／LF 互換。AGENTS.md 警告過「整檔重寫代表換行被改了」，但這些檔案本身就是髒的，使每次 diff 與合併都有雜訊、容易衝突。
   建議：獨立做一次 `git add --renormalize .` 的 commit，不混任何功能。

6. **`docs/TODO.md` 在 master 上已過時。**
   M23 五項子任務都標「進行中：ChatGPT」；其中「手機工具列單列」在 `ai/chatgpt` 已完成（`[x]`），但那個變更沒進 master，所以 master 的 TODO 與實況不符。另一方面，TODO 表示 M23 是 ChatGPT 的進行中工作，卻沒有任何人在推它的分支。

7. **CI 沒有為 master 把關。**
   - `deploy.yml` 只跑 `npm run build`，不跑測試與大小檢查；`verify.yml` 設為 `branches-ignore: [master]`，所以直接推到 master 的內容既不會跑 `verify`，測試壞了也照樣部署。
   - AGENTS.md 要求「推 master 前跑 verify」，但這只靠人記得，沒有機器強制。建議 deploy 的 build job 改成 `npm run verify`。

8. **「主資料夾只給使用者看與合併，助手不直接改」與實況衝突。**
   本次對話（及先前 M19 等工作）Claude 就在主資料夾 `xiuxian-game` 的 `master` 上直接工作與 commit，違反 AGENTS.md「並行作業流程」。`ai/claude` worktree 反而閒置且過期。需要決定：Claude 作為整合者可以在主資料夾操作（修改規則），或改回用 `ai/claude`。
