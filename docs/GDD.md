# 《一念輪迴》遊戲設計文件（暫定名）

> 版本：v0.1 草稿
> 類型：文字修仙｜放置掛機 × 人生模擬
> 平台：網頁（單頁、純前端、本機存檔）

本文件是開發的唯一依據。文件裡的**節奏目標**是規格，**數值**只是初始猜測，要靠模擬腳本調到符合節奏目標為止。

---

## 1. 一句話概念

每一世都是一段會自動流逝的修仙人生：修為自己累積，奇遇不時找上門，壽元耗盡就轉世，帶著前世的道韻重來。

## 2. 兩種類型如何結合

| 來源 | 在本作中的對應 |
|---|---|
| 掛機：數值自動成長 | 修為隨時間自動累積，年齡同步增加 |
| 掛機：轉生（prestige） | 死亡後轉世，用「道韻」買永久加成 |
| 人生模擬：隨機出身 | 每世開局擲靈根、屬性、出身 |
| 人生模擬：事件與抉擇 | 每隔一段時間觸發奇遇，選擇影響這一世 |
| 人生模擬：一生回顧 | 死亡時列出享年、最高境界、關鍵事件 |

設計意圖：前幾世壽命短、事件密集，玩起來像人生模擬；境界越高壽命越長，玩起來越像掛機。

## 3. 核心循環

**單世循環（分鐘級）**

```
開局擲骰 → 自動修煉 → 觸發奇遇並抉擇 → 突破境界（延長壽元）→ … → 壽元耗盡
```

**跨世循環（小時級）**

```
死亡 → 一生回顧 → 結算道韻 → 購買輪迴天賦 → 轉世
```

## 4. 時間模型

- 現實 1 秒 = 遊戲 1 個月（速度 ×1），可切換 ×1／×2／×4
- 所有系統以「月」為最小單位（1 tick = 1 個月）
- 抉擇事件出現時時間暫停；設定裡可開「自動抉擇」，由系統選第一個選項
- 時間比例放在設定檔，這是最需要試玩後調整的數值

## 5. 角色

### 5.1 屬性（每世開局隨機，範圍 1–10）

| 屬性 | 作用 |
|---|---|
| 根骨 | 修煉速度 |
| 悟性 | 大境界突破成功率 |
| 氣運 | 好事件的權重、歷練收穫 |
| 心性 | 降低突破失敗的損失、抵抗心魔事件 |

### 5.2 靈根

| 靈根 | 修煉倍率 | 出現權重 |
|---|---|---|
| 雜靈根 | ×0.6 | 50 |
| 三靈根 | ×1.0 | 35 |
| 雙靈根 | ×1.5 | 13 |
| 天靈根 | ×2.5 | 2 |

### 5.3 出身

農戶（無加成）、商賈（初始靈石多）、修仙世家（初始附帶一顆聚氣丹、修煉 +10%）、孤兒（氣運 +2、初始靈石為 0）。第一版只做這四種。四種出身抽中的權重相同；初始靈石：農戶 10、商賈 50、修仙世家 10、孤兒 0（M1 初始值）。

### 5.4 開局

10 歲開始，境界為凡人。開局可重擲屬性 1 次（輪迴天賦可增加次數）。

## 6. 境界與修煉

### 6.1 境界表（第一版範圍）

| 境界 | 階段 | 壽元上限 | 修煉倍率 | 進入方式 |
|---|---|---|---|---|
| 凡人 | — | 80 | ×1 | 開局 |
| 練氣 | 一層至九層 | 120 | ×1 | 修為滿 50 自動引氣入體 |
| 築基 | 初期／中期／後期 | 200 | ×3 | 練氣九層圓滿後手動突破 |
| 金丹 | 初期／中期／後期 | 500 | ×6 | 築基後期圓滿後手動突破；第一次通關到此結束這一世，之後的世通關後繼續活（第 23 節，M12） |
| 元嬰 | — | 1000 | ×6 | 金丹後期圓滿後手動結嬰，需要神光 4 級（第 23 節）；進入元嬰即「元嬰大成」，這一世結束，是新的終局 |

### 6.2 修煉公式（初始值）

```
每月修為 = 1.0 × 靈根倍率 × (1 + 根骨 × 0.05) × 境界倍率 × 日常安排倍率 × (1 + 出身加成) × (1 + 輪迴加成)
```

出身加成目前只有修仙世家的 +10%。各層需求四捨五入取整（M5 調整後九層為 762）。

### 6.3 修為需求（初始值）

- 練氣第 n 層升下一層：`128 × 1.25^(n-1)`（一層 128，九層約 762，九層合計約 3302；M5 由 `100 × 1.5^(n-1)` 調整）
- 築基初期／中期／後期：`4500 × 1.8^n`，約 4500／8100／14580（M5 由 5000／10000／20000 調整）
- 金丹初期／中期／後期：`16000 × 1.8^n`，約 16000／28800／51840（M14 調整，原為 60000）

### 6.4 突破

- **小境界**（練氣各層、築基各期）：修為滿了自動升級
- **大境界**（練氣→築基、築基→金丹）：修為滿後卡在瓶頸，需玩家手動突破

| 大境界 | 基礎成功率 | 悟性加成 | 丹藥加成 |
|---|---|---|---|
| 練氣→築基 | 30% | 每點 +2% | 築基丹 +20% |
| 築基→金丹 | 15% | 每點 +2% | 第一版無 |
| 金丹→元嬰 | 5% | 每點 +2% | 無；需神光 4 級，之後每級 +8%（M13） |

失敗：損失當前修為的 `30% − 心性 × 2%`，可再次嘗試。

## 7. 日常安排（掛機時的決策）

同一時間只能選一項，隨時可切換。

| 安排 | 修為 | 其他效果 |
|---|---|---|
| 閉關修煉 | 100% | 事件頻率減半 |
| 外出歷練 | 30% | 事件頻率加倍，有機會獲得靈石與丹藥，有極低機率身亡 |
| 採藥營生 | 20% | 每月穩定獲得靈石 |
| 走訪渡口（練氣起，M18） | 30% | 事件頻率 ×1.5，偏向散修與渡口事件（含殘卷），沒有靈石收入 |

## 8. 資源與物品

- **修為**：升級用
- **靈石**：貨幣，在坊市買丹藥
- **壽元**：年齡達到壽元上限即死亡

| 丹藥 | 效果 |
|---|---|
| 聚氣丹 | 立即獲得一筆修為（依當前境界換算） |
| 築基丹 | 練氣→築基成功率 +20%，突破時消耗 |
| 延壽丹 | 壽元上限 +10 年，每世最多服用 3 顆 |

M2 初始值：聚氣丹 20 靈石、立得當前階段所需修為的 25%（卡在瓶頸時不能服用）；築基丹 500 靈石，於嘗試突破時消耗，成敗皆然；延壽丹 300 靈石。有每世上限的丹藥，持有加已服達上限後坊市不再販售。

**丹毒（M15）**：聚氣丹在同一階段內服得越多，藥力越淡。第 1、2、3 顆分別是原效果的 100%、60%、30%（`items.json` 的 `falloff`），第 4 顆起不能再服；換到下一個階段重新計算。起因：一直採藥、有錢就買丹吃，300 世第一世有 299 世金丹（平均 39 歲），丹藥蓋過了閉關。存檔版本 11 加入 `pillStage`、`pillCount`。

### 8.1 採藥丹修檢查

`npm run sim -- 300 1 1 herb` 與 `npm run sim -- 300 1 16 herb` 模擬「永遠採藥、有錢就買聚氣丹並服用」，作為丹藥不得蓋過閉關的回歸檢查。通過標準：第一世平均止步不高於 simple（練氣 6.4 層）。M15 之後結果為練氣約 3–4 層，16 世內已築基 23%、通關 1%，遠慢於 mixed。之後任何新增的修為來源或丹藥改動，都要重跑這項。

歷練與採藥的收穫（M2 初始值）：採藥每月穩定 3 靈石；歷練每月 40% 機率得 1–3 靈石、1% 機率拾得聚氣丹、0.003% 機率身亡（整世都在歷練約 4%）。

突破到金丹即通關：進入通關畫面，可直接重新開局（完整一生回顧在 M4）。

## 9. 事件系統（人生模擬的核心）

- 每隔 16–48 個月（隨機，M6 由 12–36 調整）觸發一次，受日常安排影響
- 從事件池中，依條件篩選後按權重抽取；氣運會提高「好事件」的權重
- 分兩種：**見聞**（無選項，只寫入日誌）、**抉擇**（2–3 個選項，每個選項有多種加權結果）
- 事件可設旗標，用來做連鎖事件與避免重複
- 第一版目標：20 個事件，其中至少 8 個抉擇事件、2 組連鎖事件

### 事件資料格式

```json
{
  "id": "cave_001",
  "type": "choice",
  "title": "山中古洞",
  "text": "你在採藥途中發現一處被藤蔓遮蔽的洞口，洞內隱隱有靈氣流出。",
  "weight": 10,
  "tone": "good",
  "conditions": {
    "realmMin": "lianqi",
    "ageMin": 16,
    "flagsNot": ["cave_001_done"]
  },
  "choices": [
    {
      "text": "入洞一探",
      "outcomes": [
        { "weight": 60, "text": "洞中有前人遺留的丹瓶。", "effects": { "items": { "juqi_dan": 1 }, "flags": ["cave_001_done"] } },
        { "weight": 30, "text": "洞內空無一物，白走一趟。", "effects": { "flags": ["cave_001_done"] } },
        { "weight": 10, "text": "洞中妖獸暴起，你重傷而逃。", "effects": { "lifespan": -5, "flags": ["cave_001_done"] } }
      ]
    },
    {
      "text": "記下位置，日後再來",
      "outcomes": [
        { "weight": 100, "text": "你在地圖上做了記號。", "effects": { "flags": ["cave_001_marked"] } }
      ]
    }
  ]
}
```

可用的 effects：`cultivation`、`spiritStones`、`lifespan`、`attributes`、`items`、`flags`、`death`。

### 事件資料格式的擴充（M3）

- **conditions** 除 `realmMin`、`ageMin`、`flagsNot` 外，另有 `realmMax`、`ageMax`、`flags`（需具備全部旗標，連鎖事件用）、`schedules`（限定日常安排）、`bottleneck`（true 表示只在卡瓶頸時出現）。年齡單位是歲。
- **maxPerLife**：每世最多出現幾次，預設 1，因此不必為了避免重複而替每個事件寫旗標。
- **scheduleWeights**：依日常安排調整抽取權重的倍率，例如 `{ "adventure": 3 }`。
- **見聞**（`type: "anecdote"`）沒有 `choices`，可選擇性帶 `effects`；**抉擇**的效果寫在各選項的結果裡。
- **選項的 `requires`**：`{ spiritStones, items }`，不足時按鈕停用並標明缺什麼。每個抉擇至少要有一個沒有前提的選項。
- **M16 的進階前提**：`requires` 另有 `attributes`（屬性下限，如 `{ "insight": 7 }`）與 `fragments`（需持有的殘卷 id，跨世累積）。不足時按鈕停用，屬性寫明門檻，殘卷只寫「一則尚未讀過的舊聞」，不洩漏殘卷名稱。選項上限由 3 個放寬為 4 個，且仍要有一個沒有前提的選項。進階選項只給更穩或多一條路的結果，獎勵不超過同事件的既有選項，不加快進度。殘卷門檻選項的文字只用該殘卷已公開的內容，不得碰 `docs/WORLD.md` 第 14.3 節。
- **結果的 `weightPerAttribute`**：每點屬性額外增加的權重，例如心魔事件裡心性越高越容易守住靈台。
- **效果語意**：`cultivation` 是當前階段所需修為的比例（0.2 = +20%，負值為損失，最低扣到 0，卡瓶頸時增加無效）；`lifespan` 增減壽元**上限**（年），與延壽丹同一欄位；`attributes` 增減後最低為 1；`spiritStones`、`items` 增減後最低為 0。
- **M24 的領土條件**：`conditions` 另有 `territoryConflict`（所在地領土正在易手）與 `sectInfluence`（所在地落入開放宗門的靈脈圈），皆為 true 時才出現；規格見第 28 節。
- 資料載入時會檢查：要求的旗標必須有某個事件結果會設定它，物品、境界、日常安排的 id 都必須存在。

### 事件觸發（M3）

- 每月累加「日常安排的事件頻率倍率」，累積量達到門檻（16–48 之間隨機，M6 調整）就抽一個事件，然後歸零並重抽門檻。因此閉關約每 64 個月、採藥約 32 個月、歷練約 16 個月一次，中途切換安排也會正確計算。
- 抽取權重 = 基礎權重 × 安排倍率；好事件再乘以 `(1 + 氣運 × 0.05)`。
- 抉擇出現時時間暫停；設定裡的「自動抉擇」會選第一個前提滿足的選項。選擇結果直接寫入日誌，數值變化另外標在該行下方。
- M3 模擬（1000 世、抉擇隨機選）：每世抉擇事件平均 13.8 個（目標 8–15），事件致死約 1.8%。

## 10. 死亡與輪迴

### 10.1 死亡

壽元耗盡，或事件結果帶有 `death`。

### 10.2 一生回顧

顯示：出身與靈根、享年、最高境界、突破次數、這一世的關鍵事件（取 5 條）、獲得的道韻。

### 10.3 道韻結算（初始值）

- 練氣每層 5 點
- 築基每期 50 點
- 金丹 250 點

（M5 由 1／10／50 調整，見下方 M5 說明。）
- 首次達成某境界額外加倍一次

M4 的實作：每個到達過的階段依境界給點數（資料檔 `daoYun` 欄位，凡人 0）。「首次達成」以階段為單位，跨世只算一次，該階段的點數多加一倍（倍率放在設定檔 `daoYunFirstTimeMult`）。例如第一世練到練氣六層得 6 加 6 共 12 點，之後再到練氣六層只得 6 點。結算只在死亡或通關時做一次，不會重複入帳。

一生回顧的關鍵事件依分數挑 5 條：突破成功 5、引氣入體 2、拾得丹藥 0.8，事件取資料裡的 `highlight`（預設抉擇 1、見聞 0.5，連鎖結局 4），同分取較近的，最後依時間排序。收尾句依死因與持有物品挑選，文字放在 `text.json` 的 `review`。

### 10.4 輪迴天賦（永久）

| 天賦 | 效果 | 上限 |
|---|---|---|
| 宿慧 | 修煉速度每級 +12% | 30 級 |
| 天眷 | 開局重擲次數 +1 | 5 級 |
| 福緣 | 氣運 +1 | 3 級 |
| 遺澤 | 保留上一世 10% 靈石 | 5 級 |
| 道心 | 突破失敗的修為損失 −5% | 4 級 |
| 神光 | 結嬰的門檻（4 級）與之後每級 +8% 成功率（M13） | 6 級 |

每級價格遞增，公式放在資料檔。

M4 初始價格：第 n 級的價格 = 無條件進位（起始價 × 成長率^目前等級）。宿慧 2、×1.25（M5 調整；原為 ×1.35）；天眷 8、×2；福緣 10、×2.2；遺澤 6、×1.8；道心 12、×2。天賦只能在一世結束後（死亡或通關）購買，購買後再轉世，這樣天眷、福緣、遺澤才會套用到新的一世。

M4 模擬（策略：優先買宿慧，300–400 場戰役）：第二世開局約 3 級宿慧（+15%），到練氣五層的平均年數從 66.3 年降到 58.9 年（約 −11%），平均最高進度從 5.64 階段升到 5.98。在目前的練氣需求曲線（每層 ×1.5）下，線性的修煉加成只換到少量進度，連續 12 世仍幾乎沒有人築基，與第 13 節「首次築基第 3–5 世」差距很大，M5 已調整，見下。

**M5 調整**：練氣需求曲線改為 `128 × 1.25^n`（成長變平，讓倍率能換到更多層），築基改為 `4500 × 1.8^n`（M6 事件擴充後再微調過）；道韻改為練氣 5、築基 50、金丹 250，讓每世能買到足夠的宿慧；宿慧每級 +12%、上限 30 級、價格成長 ×1.25。第一世因為起始需求略升，仍維持 20 多分鐘、止步練氣五到七層。

### 10.5 每世目標（存檔 v12）

開局擲骰時依命盤抽出至多三個目標（`data/goals.json`），每個群組（修為、壽數、見聞）至多一個，`minLives` 限制要走完幾世才會抽到。目標的進度全由既有狀態算出（境界、年歲、事件旗標、見聞數、本世取得的殘卷），`core/goals.ts` 是純函式，沒有新的追蹤欄位。

- 只作收藏：達成次數記在 `meta.goals`，**不給道韻、不動任何數值**。若日後要給道韻，需先回到 10.3 並用 `npm run sim` 佐證。
- 過程中在「本世目標」區看進度，死後在一生回顧看結果。
- 一生回顧多一段「與上一世相比」：壽數、走得多遠、出身是否不同，由 `meta.lastLife` 與本世結果比出（句子在 `text.json` 的 `versus`）。
- 存檔 v11 → v12：擲骰中的舊檔照世界種子補抽目標；進行中與已結束的舊檔不補。

## 11. 離線進度

- 離線期間視為閉關修煉，修為與年齡照常推進
- 不觸發任何事件（這是離線的代價）
- 遇到以下任一情況即停止：修為卡在大境界瓶頸、壽元剩餘不足 10%
- 因此玩家不會在離線時死亡
- 回來時顯示「閉關 X 年，修為增加 Y」

M5 的實作：`core/offline.ts` 的 `applyOffline(state, 經過毫秒, data)`，離線一律以「閉關修煉」的倍率計算，只推進年齡與修為，不給靈石、不做歷練判定、不抽事件、不動亂數。最多計算 `offlineMaxHours`（預設 168）小時，且單次最多閉關 `offlineMaxYears`（預設 20）年，避免回來時壽元耗掉大半，少於 `offlineMinSeconds`（預設 60）秒不算；壽元剩餘低於 `offlineStopLifespanRatio`（預設 10%）時停在那一個月，因此不會老死。若停下時正在等待抉擇，或已死亡、通關，則不處理。最後一次存檔的現實時間另存在 localStorage（`xiuxian-last-seen`），不放進存檔本體，所以存檔版本不變。載入時與分頁回到前景時都會補算。

M8 的閉關見聞：閉關月數大於 0 時，在閉關結束的年齡多寫一筆 `retreat` 日誌，只記 `retreatMonths` 與結束原因 `stop`（`elapsed`、`bottleneck`、`lifespan`），文字由介面組出，所以不動亂數、不影響任何數值。見聞依閉關長短分三檔，門檻是 `offlineRetreatTierYears`（預設 `[8, 15]` 年：未滿 8 年為短、15 年以上為長）；卡瓶頸或壽元將盡時，後面再接一句對應的補句。變體由閉關月數除以變體數的餘數決定。因為 1 秒 = 1 個月，離線 1 分鐘就是 5 年，所以離線 1 分鐘（5 年，最低門檻）到不滿 96 秒為短檔，96 秒到 3 分鐘為中檔，3 分鐘以上為長檔（單次閉關受 `offlineMaxYears` 限制，最多 20 年）。`LOG_KINDS` 新增 `retreat`，舊存檔沒有這種紀錄，存檔版本不變。

## 17. 文字語氣

基調是正經仙俠，偶爾冷冷地吐槽一句。所有玩家看得到的文字（事件、日誌、一生回顧、物品說明）都照這個標準寫。

### 17.1 規則

- 敘述用正經的仙俠筆調：句子短、略帶文言、以「你」稱呼主角
- 吐槽要冷面、輕描淡寫，通常只放在最後一句，前面照樣認真鋪陳
- 大約每三到四則文字裡有一則帶吐槽，其餘保持正經，否則笑點會失效
- 吐槽的對象是主角的處境和修仙界的常理，不嘲笑玩家
- 敘述者不現身、不對玩家說話、不提「遊戲」「數值」這類詞
- 不用網路流行語、現代用語、表情符號
- 重場面不吐槽：大境界突破成功、連鎖事件的結局、通關

### 17.2 範例

見聞（帶吐槽）：

> 三十七歲秋，你於山澗旁靜坐三日，忽有所悟。起身時方知，所悟者不過是腿麻了。

抉擇結果（帶吐槽）：

> 石台上置一玉瓶，瓶身古篆斑駁。你屏息啟封，內有丹藥一顆，另附字條：「存放三百年，藥效自負。」

大境界突破成功（不吐槽）：

> 丹田之中靈氣如潮，百脈俱震。一炷香後，天地復歸寂靜。你已築基。

一生回顧（收尾帶一點）：

> 享年一百一十九歲，終身練氣六層。臨終之際你望著窗外流雲，想起那顆始終沒捨得吃的聚氣丹。

### 17.3 反例

> 你撿到一顆丹藥，真是太幸運了哈哈！（太白話、有語氣詞）

> 恭喜玩家獲得聚氣丹 ×1，修為 +50！（敘述者現身、出現數值用語）

> 這洞穴簡直離譜，誰家前輩這樣藏東西啊。（整句都在吐槽，沒有正經的鋪陳）

### 17.4 殘卷的文體

殘卷（第 18 節）是世界裡的文獻，不是敘述者的聲音，規則略有不同：

- 不必稱「你」，照該文獻自己的口氣寫（宗誌、帳本、手札、口訣、公文），口氣對照表見 `docs/WORLD.md` 第 17.2 節
- 每份不超過四句，或四行帳目
- 吐槽來自文獻本身的一本正經，例如抄帳人懶得抄、經辦人只在乎格式；不另加敘述者的評語
- 第 17.1 節其餘規則照用：不用現代用語，不提「遊戲」「數值」
- 給殘卷的事件，敘述只寫得到文書的經過，不替內容下結論

範例：

> 是年，簿冊添「道韻留存」一欄。事由：依約。立約人：□□（名已繳銷）。
> 經辦司吏按：欄寬不足，往後字請寫小些。

## 18. M6：殘卷與史料

> 本里程碑在 M5 完成後新增。內容設定（三界、歷史、十四份殘卷的清單與範例）見 `docs/WORLD.md` 第 12–17 節，本節只寫系統規格。
> 以下的資料格式是建議，實作前照慣例先提計畫；格式有更好的做法可以改，節奏目標與驗收條件才是規格。

### 18.1 目的

讓輪迴累積的不只是數值，還有「知道的事」。玩家每一世撿到一兩份立場不同的舊文書，跨越好幾世，自己拼出天梯為何斷絕、道韻從何而來。

### 18.2 範圍

做：

- 殘卷資料檔與格式檢查
- 事件結果可以給殘卷
- 殘卷跨世保留，存檔結構升版
- 「殘卷錄」頁面
- 事件從 20 個擴到 40 個
- 模擬腳本增列殘卷指標

不做：

- 殘卷不給任何數值加成，集滿也沒有獎勵數值（避免動到第 13 節的節奏）
- 不做勢力聲望、陣營、可互動的角色
- 不做跨世的世界狀態（世年、上一世的世界）。年號在 M10 另以「只有名字、不帶年數」的方式加入（第 22 節），不改變這一條。

### 18.3 殘卷資料

`src/data/fragments.json`，每份一筆：

```json
{
  "id": "f06",
  "title": "通濟行舊帳・供奉冊",
  "topic": "juetong",
  "source": "帳本",
  "stance": "tongji",
  "era": "絕通前三十年起",
  "tier": 2,
  "text": "絕通前三十年，代太衡宗解送上界供奉，靈石八萬。回執：無。\n絕通前二十九年，同上，靈石九萬。回執：無。\n抄者按：以下二十八年皆同，不錄。"
}
```

| 欄位 | 說明 |
|---|---|
| `topic` | 主題，殘卷錄依此分組。第一批兩個：`juetong`（絕通）、`sanjie`（三界與九境） |
| `source` | 文獻種類，直接顯示 |
| `stance` | 立場：`taiheng`、`yedu`、`tongji`、`youming`、`shangjie`、`none`；顯示名稱放資料檔 |
| `era` | 年代，直接顯示；一律以絕通前後紀年 |
| `tier` | 層級 1–3，決定何時拿得到 |
| `fixed` | 選填，true 表示不進抽取池，只由指定方式取得（目前只有 f14） |

十四份的編號、標題、層級與應透露的內容見 `docs/WORLD.md` 第 17.3 節，其中五份已有定稿文字（第 17.4 節），其餘九份照樣本的口氣寫。

載入時檢查：id 不重複、`tier` 在 1–3、`stance` 與 `topic` 在允許清單內、`text` 不為空。

### 18.4 取得與保存

- **效果擴充**：`Effects` 新增 `fragment`，兩種寫法擇一
  - `{ "id": "f01" }`：給指定的一份
  - `{ "maxTier": 2 }`：從「尚未持有、已解鎖、層級不超過 2、非 `fixed`」的殘卷中等機率抽一份
- **條件擴充**：`EventConditions` 新增 `fragmentAvailable`（數字）。只有在還抽得到層級不超過該數字的殘卷時，事件才會出現，避免玩家遇到事件卻沒有東西可拿。
- **解鎖**：一層無條件；二層需曾達築基（`meta.reached` 含 `zhuji:0`）；三層需曾達築基後期（`meta.reached` 含 `zhuji:2`）。
- **f14**：首次通關時固定取得，顯示在通關畫面。
- **保存**：`Meta` 新增 `fragments: string[]`。`SAVE_VERSION` 由 6 升到 7，遷移函式補上空陣列；匯入存檔時檢查每個 id 都存在。
- **顯示**：`Changes` 新增 `fragment`，日誌該行下方標出「得殘卷《標題》」，文字不寫進敘述。
- 抽取在 `core/` 內用可設種子的亂數完成。資料載入時檢查事件引用的殘卷 id 存在。

### 18.5 介面

- 右側新增「殘卷錄」按鈕，顯示已得與總數（例如 3／14），有新殘卷時加標記
- 殘卷錄依主題分組；每份顯示標題、來源、立場、年代與全文
- 未得的只顯示「（未得）」，不透露標題
- 卷首固定一句：「這些你都讀過，只是不記得了。」
- 擲骰、進行中、一生回顧、通關各畫面都能打開；手機寬度下可正常閱讀

### 18.6 事件擴充

- 事件總數由 20 個擴到 40 個，其中至少 10 個的某個結果會給殘卷
- 取得殘卷的場合舉例：渡頭集的舊書攤、荒廢洞府的遺物、通濟行夥計清倉、路過的太衡宗外門弟子遺落、借宿的野渡客臨別相贈
- 新事件照 `docs/WORLD.md` 第 11 節的對照表寫，地名與勢力名只用該文件第 15、16 節列出的
- 新事件不得讓修煉明顯變快；以修為、丹藥為獎勵的新事件，數量與幅度比照現有事件

### 18.7 節奏目標

| 指標 | 目標 |
|---|---|
| 每世新得殘卷 | 前五世平均 1–2 份 |
| f01 與 f02 都到手（第一組互相矛盾的說法） | 第 3 世結束前 |
| 集滿 14 份 | 第 10–14 世，即通關前後 |
| 第 13 節原有的各項指標 | 不變，mixed 策略仍在區間內 |

`npm run sim` 增列前三項並標示通過與否。

### 18.8 驗收條件

- 取得殘卷後轉世，殘卷錄內容還在；重新整理頁面後也還在
- 版本 6 的舊存檔能正常載入，殘卷為空
- 同一主題下至少能並排讀到兩份立場相反的記載
- 模擬結果落在第 18.7 節與第 13 節的目標內
- 測試全過；`fragments.json` 的格式錯誤會指出是哪一份的哪個欄位

### 18.9 M6 實作結果

- **`chance` 擴充**：殘卷效果新增選填的 `chance`（0–1，只能搭配 `maxTier`），讓見聞也能「有機率」給殘卷。起因是事件池只有 40 個、每世約 27 個事件，幾乎每個事件每世都會出現一次，調事件權重幾乎沒有效果，真正決定收集速度的是「見聞必給」與選項結果的機率。目前五個給殘卷的見聞都是 `chance: 0.3`。
- **事件間隔**：40 個事件讓原本被「池子耗盡」壓住的抉擇事件數回升到 17 個，超出第 13 節的 8–15，所以把觸發門檻區間從 12–36 拉到 16–48（第 9 節同步更新）。
- **殘卷來源**：f01 由「遺落的文書」（太衡宗外門弟子）固定給、f02 由「野渡行腳客」固定給，讓第一組互相矛盾的說法穩定在前三世到手；其餘用 `maxTier: 3` 從已解鎖的殘卷中抽，所以築基之前只會抽到一層。f14 由首次通關固定取得。
- **二層／三層解鎖**同時看跨世紀錄與本世目前的進度，不必等到這一世結算。
- 指標（種子 1–4，`npm run sim -- 300 <種子> 16 [simple|mixed]`）：

| 指標 | simple | mixed | 目標 |
|---|---|---|---|
| 前五世每世新得殘卷 | 約 1.2–1.3 份 | 約 1.2 份 | 1–2 |
| f01 與 f02 都到手 | 中位數第 3 世 | 中位數第 2–3 世 | 第 3 世結束前 |
| 集滿 14 份 | 中位數第 13 世 | 中位數第 12 世 | 第 10–14 世 |

- 集滿的世數貼著目標區間的上緣（simple 最慢），若日後要放慢或加快，調 `fragmentAvailable` 事件的 `chance` 與選項權重最直接。

## 19. M7：天下圖與每世重生的世界

> 本里程碑在 M6 完成後新增。內容設定（九渡洲、名庫、世局候選池、名稱欄位）見 `docs/WORLD.md` 第 18–20 節，本節只寫系統規格。
> 這是第 15 節的明確例外，範圍只到「看」。以下資料格式是建議，實作前先提計畫；節奏目標與驗收條件才是規格。

### 19.1 目的

讓玩家每次轉世都進入一個**不一樣的世界**：出生地、國名、宗門名、天下局勢都不同，並且在一世之內隨年齡推進而變化。玩家可以打開一張只讀的天下圖，看到自己的位置、各國與各宗門。

### 19.2 範圍

做：

- 「世界種子」：每世生成一份世界，存進存檔，重新整理不變
- 名庫、地域骨架、世局候選池的資料檔與格式檢查
- 世界生成與「某個年齡時的世界快照」兩個純函式
- **名稱欄位**：事件、日誌、殘卷、物品說明、一生回顧的文字全部改用欄位，顯示時填入當世名稱
- 殘卷錄與一生回顧用當世的名稱填入
- 天下圖（SVG）：地域、國家顏色、宗門標記、渡口標記、「你在這裡」、點選簡介
- 擲骰畫面顯示出生地，重擲會換一個世界
- 地圖按鈕上的變化提示

不做：

- 不能移動、前往、加入宗門（M22 起可旅行，見第 26 節；仍不能加入宗門）；出生地與世界**不影響**修煉、道韻或任何第 13 節與第 18.7 節的指標（M17 起，世局可影響坊市價格與少數事件的出現條件，見第 24 節）
- 不顯示年數或「多久以前」
- 世與世之間沒有延續：不存世年、不存上一世的世界
- 不做國家或宗門的互動、聲望、陣營
- 不做縮放、拖曳；一張固定的圖

### 19.3 世界種子

- `GameState` 新增 `worldSeed`（整數）。存檔版本升一版，遷移用既有的 `rngSeed` 雜湊補一個。
- **生成世界時不消耗亂數、不動 `rngSeed`**：世界種子由擲骰完成後的 `rngSeed` 經固定的雜湊算出，世界生成另用自己的亂數序列。理由：不碰既有亂數，`npm run sim` 才不會位移。
- 重擲命盤會重新算出一個世界種子；一旦開始修行就固定。
- 世界本身**不存進存檔**，由種子重算（函式必須是確定性的）。

### 19.4 世界資料

三份資料檔，建議如下（欄位名稱實作時定案）：

**`src/data/worldNames.json`**：每個欄位一個名庫，見 WORLD 第 18.4 節的規則與數量下限。欄位：`countries`、`guards`、`merchants`、`wanderers`、`greatSects`（舊守梯大宗）、`schools`、`capitals`、`villages`、`markets`、`mountains`。

**`src/data/map.json`**：骨架，每世都一樣：

```json
{
  "regions": [
    { "id": "north", "name": "北方", "aura": "…", "path": "M…", "label": [x, y], "host": "guard" }
  ],
  "ferries": [ { "id": "f1", "region": "north", "x": 0, "y": 0 } ],
  "stairs": { "x": 0, "y": 0, "text": "階上有東西。去過的人都說沒有。" }
}
```

**`src/data/worldEvents.json`**：世局候選池，以欄位寫成：

```json
{
  "id": "great_sect_fall",
  "kind": "sectState",
  "target": "greatSect",
  "to": "fallen",
  "ageMin": 40,
  "ageMax": 120,
  "weight": 3,
  "group": "great_sect_a",
  "note": "{target}覆滅，山門荒廢。"
}
```

| 欄位 | 說明 |
|---|---|
| `kind` | 見 WORLD 第 19.2 節：`owner`、`merge`、`split`、`polityNew`、`rename`、`sectState`、`sectRank`、`sectNew`、`ferry` |
| `target` | 欄位名或角色（如 `greatSect`、`school`、`country`），生成時綁定到具體對象 |
| `ageMin` / `ageMax` | 年齡窗（歲） |
| `weight` | 被抽中的權重 |
| `group` | 互斥群，同群至多抽一條 |
| `note` | 顯示的一句話，內含名稱欄位 |

載入時檢查：id 不重複；`kind`、`target` 在允許清單內；年齡窗合法；`note` 只用允許的欄位；名庫數量足夠；**所有資料檔中不得直接出現參考名**（太衡宗、通濟行、野渡、垣下、渡頭集、青垣山），錯誤訊息指出是哪一筆的哪個欄位。

### 19.5 世界生成與快照

`core/world.ts`，純函式：

- `generateWorld(worldSeed, data)`：抽出出生地域、各欄位的名字、起點歸屬與宗門起點狀態，再從候選池抽出十到十四條變化並排好年份，回傳完整的世界設定。
- `worldAt(world, ageYears)`：套用 `年齡 ≤ ageYears` 的所有變化，回傳當下的快照（各地域歸屬、國名、宗門名稱與狀態、位階、渡口狀態、最近一兩條 `note`）。
- 變化的抽取保證：主角三十到七十歲之間至少有一次變化；同一互斥群只抽一條；不會對已覆滅的宗門再做變化。

快照可重算，不存進存檔。每月 tick 不計算，只有開啟地圖、擲骰畫面與要判斷提示時才算。

### 19.6 名稱欄位

- 欄位：`{guard}`、`{merchant}`、`{wanderers}`、`{village}`、`{market}`、`{mountain}`、`{country}`（WORLD 第 20 節）。
- `core/` 或 `ui/` 提供一個「填入欄位」的函式，輸入模板與當世的世界，輸出文字。模板裡出現不認得的欄位要報錯，不要默默顯示原文。
- 需要改成欄位的文字：`events.json`（標題、敘述、選項、結果）、`fragments.json`（標題、內文、立場名稱）、`text.json`、`items.json` 若有。
- 殘卷的立場名稱改用欄位（例如立場 `taiheng` 顯示為 `{guard}`），殘卷錄與一生回顧顯示時填入。
- 日誌只存事件 id 與索引，文字在顯示時組出，因此舊日誌隨之使用當世名稱。一生回顧的關鍵事件同理。

### 19.7 介面

- 上方列新增「天下圖」按鈕，有新變化時加「●」（已看過的狀態存在 localStorage，不放進存檔本體）。
- 地圖以一張 SVG 畫出六處地域，各國一種顏色（依當世的國家，顏色循序分配）；極北荒原灰色；宗門用小標記，位階決定大小，狀態決定樣式（興盛實心、平穩空心、衰微虛線、閉山灰色、覆滅打叉但仍留一筆）。
- 九個渡口以小標記表示，殘階以灰色標記。
- 「你在這裡」標在當世的出生村，簡介寫村名與所屬國。
- 點地域、國家、宗門、渡口：側邊（手機為下方）顯示簡介與當前狀態；簡介由模板產生（WORLD 第 18.5 節）。

- 版本 7 的舊存檔能正常載入，並得到一個世界
- 點選地域、國家、宗門、渡口能看到簡介；亡國、覆滅的對象不再以舊樣式出現
- `npm run sim` 與 M6 的結果完全一致
- 測試全過；三份資料檔的格式錯誤會指出是哪一筆的哪個欄位
- 手機寬度下可正常閱讀與點選

### 19.10 M7 實作結果

- 世界生成（`core/world.ts`）：每世從 33 條候選池抽 10–14 條變化，三十到七十歲之間必有一次。用 2000 個種子檢查過分布與不變量，並寫成單元測試。
- 世界種子由擲骰完成後的 `rngSeed` 雜湊而來，不消耗亂數。`npm run sim` 的 simple 與 mixed 結果與 M6 逐項相同。
- 名稱欄位：事件與殘卷全部改用欄位，載入時檢查並指出是哪一筆的哪個欄位；測試另外掃描所有資料檔（名庫除外）。

## 20. 事件池擴充（M7 之後）

事件由 40 個擴到 70 個，目的是降低重玩時的重複感。沒有新增任何資料格式，只用既有的條件、效果與名稱欄位。

### 20.1 新增內容（30 個）

| 類型 | 數量 | 內容 |
|---|---|---|
| 連鎖 | 9 | 棄嬰（三段）、借宿書生（兩段，後段可得殘卷）、舊友（兩段）、石壁告示（兩段） |
| 少年 | 4 | 十到二十多歲才會遇到：私塾先生、秋收、為了蟋蟀打架、丹田微暖 |
| 壯年 | 5 | 媒人上門、親戚借貸、河水暴漲、鋪子失火、隔牆之爭 |

- 抉擇與見聞維持約六比四（17 : 13），避免抉擇事件數超過第 13 節的上限。

### 20.2 校準時發現的問題

- **少年事件不能限定「凡人」**：主角約十二歲就引氣入體，而第一個事件要等十幾歲才出現，所以限定凡人的事件幾乎不會發生（既有的「鄉里嫁娶」也是如此，每世出現率約 0.01）。少年事件改以年齡限定。
- **連鎖與年齡段事件要拉高權重**：和 70 個事件競爭時，權重與其他事件相同會讓連鎖後段幾乎看不到。連鎖前段約 30、後段約 50，年齡段專屬事件約 20–30。

### 20.3 結果（模擬，種子 1–4，simple 與 mixed）

- 第 13 節與第 18.7 節的所有指標都通過；每世抉擇事件 12.9（simple）、14.1（mixed）。
- 相鄰兩世看到的事件重疊度（Jaccard）由 0.33（40 個事件）降到 0.22（70 個事件）；每世平均看到約 18 種不同事件。
- 連鎖的完成率仍偏低（隨機選項的模擬策略下，棄嬰一線走完約 6%），真人會挑選項，實際會高一些。

## 21. 通關收藏（M9）

- 跨世資料 `meta.clears`：`{ 出身 id: 通關次數 }`，只在通關（`endLife` 的 `cleared`）時該出身加一，死亡不計。通關總次數由各出身加總得出，不另外存。
- 它不被任何公式讀取，不影響修煉、道韻、事件或任何數值，因此不影響第 13 節的指標，`npm run sim` 不受影響。
- 存檔版本 9。v8 遷移補上空的 `clears`：舊存檔沒記下過去通關的出身，無從回推，已通關過的舊玩家從 0 開始累計。讀檔時檢查出身 id 必須存在於 `origins.json`、次數必須是正整數。
- 介面：頂部「收藏」按鈕開啟與殘卷錄同款的彈窗，顯示通關總次數，並列出 `origins.json` 的每種出身（名稱、簡介、通關次數，沒通關過顯示「尚未通關」），所以新增出身會自動出現。每種出身都通關過一次時多一句收尾。說明文字在 `text.json` 的 `collection`。
- 沒有做：成就、獎勵。收藏只是紀錄，不給任何好處。
- **各出身最快年齡（M25 之後補做，存檔 v16）**：跨世資料 `meta.fastest`，鍵是「終局:出身 id」（終局為 `cleared`、`yuanying`、`huashen`），值是達成當時的年齡（月）；沒有紀錄或這次更快才更新。通關、元嬰、化神各自記，結束這一世與繼續活著的都記。不被任何公式讀取，不影響 sim。v15 遷移補上空紀錄（舊存檔沒記過年齡，無從回推）。`collectionSummary` 的每一列帶 `fastest`，介面顯示由 M26 順手接上。

## 22. 世界年號（M10）

- 年號是世人通用的紀年，只有名字（例如「承平年間」），**不帶年數**。清單在 `data/eras.json`，第 n 世（從 0 起算，n 是已走完的世數）用第 n 項；用完後從頭循環並加「後」（後永寧）。年號可由世數直接算出，不存進存檔，存檔版本不變。
- 與 `docs/WORLD.md` 第 14.1 節一致：不寫轉世隔多久，也不寫距今的年數；與第 19 節一致：地圖不顯示年數，世與世之間不存世年。年號只標示「一世比一世晚」。
- 顯示位置：修仙日誌每世開頭一則開場（`era` 日誌，記下世數，文字依世數挑，不加年齡前綴）；修行畫面狀態列姓名旁「（承平年間）」；一生回顧一行「生於承平年間」；第二世起的擲骰畫面一句「某某年間之後，隔了不知多少年，如今是某某年間。」日誌行首仍是歲數。
- 文字在 `text.json` 的 `era`，不得出現數字年數，也不得出現 `docs/WORLD.md` 第 14.3 節的真相。
- 新增日誌類型 `era`（需有 `eraIndex`）。它只是一筆日誌，不影響任何數值，`npm run sim` 不受影響。

## 23. 元嬰以上的擴充（M11 設計，M12 起實作）

> 狀態：設計已通過審閱（2026-10-06），依第 23.10 節拆成 M12 到 M14 實作；每個里程碑開工前仍要先提實作計畫。所有數值是初始猜測，實作時要用 `npm run sim` 佐證，並回頭更新本節與第 13 節。

### 23.1 目標與限制

- 給通關後的玩家一個新目標，把總遊玩時間從 4–6 小時再延長約 4–6 小時，而不是把通關門檻往後推。
- **第一次通關的體驗完全不變**：沒通關過的玩家，金丹仍然是終點。因此第 13 節既有指標（第一世時長、首次築基、首次金丹等）不受影響。
- 只做**元嬰**一個境界。化神以上維持「只剩名字」，不做。
- 不給「世界在等你」的敘事。`docs/WORLD.md` 第 14.5 節的三件留白不回答：不寫別人是否也走通過、不寫上界光景、不寫□□是誰。

### 23.2 玩家流程

1. 第一次通關：金丹大成，結束這一世，與現在完全相同。
2. 之後的世（`meta.clears` 總數 ≥ 1）：突破到金丹時**不再結束這一世**。該世記一次通關（`clears` 加一，首次得殘卷 f14），然後繼續活在金丹，修為進入金丹的各階段。
3. 金丹圓滿後卡瓶頸，可以嘗試結嬰。成功則進入元嬰，這一世以「元嬰大成」結束，是新的終局；失敗則損失修為，可再試。
4. 沒結成嬰就壽盡，照一般死亡結算，回顧顯示終身金丹。

### 23.3 金丹期（讓金丹有東西可修）

- 金丹改為三個階段（初期、中期、後期），需求曲線 `base × growth^n`，修煉倍率高於築基。M14 實測後的數值：base 16000、growth 1.8，倍率 ×6，壽元 500，道韻每期 250（草案原為 base 60000、道韻 150，見 23.14）。
- 後期圓滿後卡瓶頸，手動結嬰。
- 沿用既有的日常安排、事件、坊市、離線進度。離線時金丹期的規則與其他境界相同（卡瓶頸就停）。
- 事件池需要新增金丹期事件（`realmMin: "jindan"`）約 15–20 個，語氣肅穆，點到為止，另案寫，不在本設計範圍。
- 已實作 23 個（`jindan_*`，9 抉擇、14 見聞）：主題是長壽者的孤獨與世人的敬畏（舊名冊、故人來訪、訃告、路人叩拜）、各方勢力的客氣（{guard} 請帖、{merchant} 作保、{wanderers} 認人）、與輪迴的隱約熟悉（夢中渡口）。刻意只給屬性（心性、悟性、氣運）、少量靈石與一次壽元 +5，修為獎勵不超過 +4%，沒有致死、殘卷與元嬰以上的描寫，避免動到第 13、23.6 節的節奏；`tests/eventpool.test.ts` 守住這些限制。
- 其中五則後續見聞串起三條選擇線：「故人來訪」依接待或隔門道謝給不同結局；「山門請帖」赴約後才有論道舊函；「礦苗之爭」依均分或判給一方留下不同後話。只用本世旗標，不新增跨世人物或存檔欄位。後段權重高於起點，讓已開啟的故事有機會收束；沒有額外數值獎勵。實測（種子 1，300 場）simple／mixed／post 的第 13、18.7、23.6 節指標全部 ✓，post 首次元嬰累計 11.2 小時。

### 23.4 神光（新的輪迴天賦）

- 世界觀對應：`docs/WORLD.md` 第 13.1 節說結嬰須借天光，梯斷後天光不再降下；第 14.5 節預留「道韻積得夠深，神魂或能自生其光」。天賦名「神光」，說明文字只能留模糊暗示，不得直說「不借天光」。
- M14 實測後的數值：上限 6 級，起始價 250、成長 ×1.5（草案原為 300；前 4 級累計約 2030 道韻）。
- **門檻**：神光至少 4 級才能嘗試結嬰；超過 4 級的每一級，結嬰成功率 +8%。
- 神光只能在一世結束後購買，與其他天賦相同。

### 23.5 結嬰突破

- 基礎成功率 5%，每點悟性 +2%，沒有丹藥加成。神光超過 4 級的每級 +8%。失敗損失當前修為 `30% − 心性 × 2% −（道心 × 5%）`，與其他大境界相同，不致死。
- 元嬰：單一階段，壽元 1000，不再有後續境界。進入元嬰即「元嬰大成」，新增一種結束方式 `yuanying`，有自己的收尾句與道韻結算（初始猜測 800，首次加倍）。
- 收藏：`meta.clears` 不動；另記元嬰次數（出身 id → 次數），收藏畫面新增一列。這是存檔欄位的擴充，需要遷移。

- sim：1000 世的單世模擬與之前逐字相同。連續轉世的戰役模擬每場的種子接在前一場之後，通關後的世現在會在金丹繼續活，亂數消耗不同，所以各戰役的數字有小幅漂移（首次築基、首次金丹的中位數與所有 ✓ 都不變，通關總遊玩時間 4.5→4.6 小時）。

### 23.13 M13 實作紀錄

- 資料格式：`breakthroughRule.requiresTalent`（天賦等級門檻）、`breakthroughRule.talentRate`（超過 `from` 級後每級加成）、境界的 `ending`（`cleared` 或 `yuanying`，預設 `cleared`）、天賦 `effect: "breakthroughAid"`。最後一個境界的 `endsLife` 必須是 `always`。

- 神光：上限 6 級、起始價 300、成長 ×1.5，只能在一世結束後購買。
- 結嬰成功以 `endLife(…, "yuanying")` 結束這一世：不加通關次數，改記 `meta.yuanying`（出身 → 次數）。結束畫面標題「元嬰大成」，階段仍是 `cleared`（沿用同一組結束畫面與輪迴天賦頁）。
- 存檔版本 10：v9 遷移補空的 `yuanying`；讀檔檢查出身 id 與次數。
- 模擬：`simulate.ts` 的 mixed 策略本來就用固定的天賦清單，不會買神光；simple 只買宿慧。所以 M13 完成後 `npm run sim` 的完整輸出（單世與兩種戰役）與 M12 逐字相同。神光與結嬰要等 M14 的 `post` 策略才會被模擬。
- 文字：神光說明、結嬰缺神光的提示、結嬰成功與元嬰大成的收尾句都不出現「天光」「梯」「絕通」，也不說光的來源。

### 23.14 M14 實測與調整

`npm run sim -- 300 1 40 post`（通關前同 mixed；通關後道韻先買神光到 4 級，再依宿慧 30、神光 6、道心 4、其餘 2 的目標均衡購買）。

**調整**：金丹需求 base 60000 → 16000；神光起始價 300 → 250。其餘維持第 23 節草案（結嬰基礎成功率 5%、悟性 +2%、神光每級 +8%、金丹道韻每階 250）。

**調整過程**（種子 1，100 場）：base 60000 時金丹期單世平均 65 分鐘，幾乎都撐到壽元上限，每世只有 35 世嘗試過結嬰，40 世內只有 26% 結嬰；降到 20000 後首次元嬰通關後再 10 世，但累計 13.3 小時、金丹期單世 45 分鐘仍偏長；降到 16000 後單世進到 37 分鐘，累計 12.5 小時；神光起始價 300 → 250 後累計降到 11.9 小時。

**結果**（300 場，每場 40 世）：

| 指標 | 種子 2 | 種子 3 | 目標 |
|---|---|---|---|
| 首次元嬰（通關後再幾世，中位數） | 9 | 9 | 8–14 |
| 首次元嬰累計遊玩（平均） | 11.9 小時 | 11.7 小時 | 8–12 |
| 金丹期單世時長（平均，神光已到門檻者） | 35.5 分鐘 | 36.0 分鐘 | 20–40 |
| 每世結嬰嘗試（平均，有嘗試者） | 3.4 次 | 3.5 次 | 2–5 |

**對第 13 節的影響**：單世模擬（1000 世）與 M13 逐字相同。連續轉世戰役的第一次通關之前的行為沒有改變，但通關後的世亂數消耗不同，所以各戰役的數字小幅漂移：simple 的首次金丹中位數維持第 10 世、通關總遊玩 4.5 小時；mixed 維持第 9 世，通關總遊玩 4.2–4.4 小時（改動前同種子為 4.2–4.3），所有 ✓ 維持。

**已知問題與限制**：
- 通關後進了金丹、但神光還沒到門檻的世（種子 2 約 240 世，占金丹期的 8%）沒有事可做，只能修到後期圓滿然後空等壽盡。這在第一次通關到買足神光之間的前幾世一定會發生。目前不處理，但這是玩家體驗上最可能被抱怨的地方，列入第 16 節待定事項。

## 24. 世局的實際影響與日常安排（M17–M18）

> 這一節把第 19 節「只讀的世界」鬆開一小塊：世局會影響坊市與少數事件，讓玩家有理由去看天下圖。所有數值是初始猜測，以 `npm run sim` 佐證。

### 24.1 世局效果（M17）

- `src/data/worldEffects.json`：每筆有 `id`、`when`（守梯宗門狀態、商行分號數下限、毀去的渡口數下限，全部成立才生效）、`market`（物品 id → 價格倍率）、`reason`（坊市旁顯示的原因，可用名稱欄位）。
- 世局由世界種子與年齡算出（第 19 節），所以效果也只是年齡的函式：不進存檔、不動亂數、存檔版本不變。價格 = 基本價 × 生效效果倍率的乘積，四捨五入，至少 1。購買、按鈕可否點擊、模擬腳本全部走 `itemPrice`。
- 事件條件新增 `world`（需要的效果 id 全部生效）與 `worldNot`（任一生效就不出現）。效果 id 就是旗標，資料載入時檢查存在。
- 初始四條：

| 效果 | 條件 | 價格 |
|---|---|---|
| 山門封閉 `guard_closed` | 守梯宗門封山 | 築基丹 ×1.6 |
| 山門興旺 `guard_prosper` | 守梯宗門興盛 | 築基丹 ×0.9 |
| 商行遍地 `merchant_wide` | 商行分號 ≥ 3 地域 | 聚氣丹 ×0.8、築基丹 ×0.9 |
| 渡口多毀 `ferries_broken` | 毀去的渡口 ≥ 2 | 延壽丹 ×1.3 |

- 新增 4 個事件使用 `world` 條件：山門前的茶棚、門內流出的丹藥、新招牌、斷渡。
- 理由：`docs/WORLD.md` 寫明築基丹由守梯大宗獨佔、商行經銷，價格隨之起伏順理成章。
- 驗收：simple 與 mixed 的第 13、18.7 節指標維持 ✓（價格起伏在世界之間大致對稱）。

### 24.2 走訪渡口與閉關坐化（M18）

**走訪渡口**
- `schedules.json` 的安排可加 `realmMin`，達到該境界才開放（未開放的按鈕不顯示，`setSchedule` 也不接受）。走訪渡口從練氣開放，修為 30%、事件頻率 ×1.5、沒有靈石與拾得物，也沒有身亡風險。
- 它的價值在事件：新增 3 個只在走訪時出現的事件（渡口的老船夫可得殘卷、渡口人多、行腳人），並讓既有的行腳客、渡口邊、船夫舊紙、茶棚傳聞四個事件在走訪時權重 ×3。
- 檢查：`npm run sim -- 300 1 1 wander` 的第一世止步不得高於 simple（目前練氣約 3–4 層）。它不應是升級的捷徑，只是用修為換殘卷與見聞。

**閉關坐化**
- `realms.json` 的境界可加 `zuohua: { daoYunPerYear }`，目前只有金丹（0.15）。在該境界修行中、沒有待決抉擇時，介面出現「閉關坐化」按鈕（會先確認）：提前結束這一世，額外換得「剩餘壽元整年數 × 每年道韻」的道韻，其餘結算與壽盡相同。
- 新增結束方式 `zuohua`（`ReviewCause`、`LogKind`、`text.json` 的日誌與三句收尾）。階段：死亡（`dead`），不算通關也不算元嬰。
- 用意：神光未到門檻、已把金丹修到後期圓滿的世，不用空等幾百年壽盡。係數刻意偏小，使「進金丹就坐化」換不到比完整走一世更多的道韻。
- `post` 策略的做法：神光未到門檻時，修到金丹後期圓滿、卡瓶頸才坐化。結果：首次元嬰仍在通關後第 9 世（中位數）、累計約 11 小時，其餘第 23.6 節指標維持 ✓。
- 存檔版本不變（只多了一個合法的 `cause` 值與日誌類型）。



## 25. 化神（M19 設計與實作）

> 狀態：設計已通過審閱（2026-10-06），依第 25.9 節拆成 M19 到 M21。所有數值是初始猜測，實作時用 `npm run sim` 佐證，並回頭更新本節與第 13 節。第 15 節因此開例外：新增化神，煉虛以上仍不做。

### 25.1 目標與限制

- 給已經元嬰過的玩家下一個目標，再延長約 4–6 小時的遊玩，而不是把元嬰的門檻往後推。
- **第一次元嬰的體驗完全不變**：沒元嬰過的玩家，元嬰仍是這一世的終點。第 13、23.6 節的所有指標不受影響。

- 不回答 `docs/WORLD.md` 第 14.5 節的三件留白。化神大成的文字只寫神魂的變化，不說來源，不說世上還有沒有別人走通過，不讓世人知道有人化神。

### 25.2 玩家流程

1. 第一次元嬰：與現在完全相同，結束這一世。
2. 之後的世（`meta.yuanying` 總數 ≥ 1）：突破到元嬰時**不再結束這一世**。該世記一次元嬰，然後繼續活在元嬰，依初期、中期、後期修煉。
3. 元嬰後期圓滿後卡瓶頸，可以嘗試化神。成功則「化神大成」，是新的終局；失敗損失修為，可再試。
4. 沒成功就壽盡或閉關坐化，照一般結算，回顧顯示終身元嬰。

### 25.3 元嬰期

- 元嬰改為三階段（初期、中期、後期），需求 `base × growth^n`，倍率高於金丹。初始值：base 32000、growth 1.8、倍率 ×12、壽元 1000。倍率與需求同比放大，使元嬰期單世時長與金丹期相近（約 35 分鐘），M21 再用 sim 調。
- 道韻每階段維持 800（為了讓第一次元嬰的道韻結算與 M18 之前相同）；M21 再看通膨。
- 元嬰期可閉關坐化（每年 0.3 道韻，剩餘壽元折算）。
- 元嬰期專屬事件約 15 個（`realmMin: "yuanying"`）放在 M21，語氣肅穆，不寫化神以上的描寫，不寫輪迴真相。

## 29. M25：加入宗門

> 狀態：M25 核心已實作（2026-10-06），M26 介面、M27 事件待做。設計草案經使用者審過。使用者選擇「任務與同門」的完整範圍、一世只入一宗可離開、好處為修煉加成加資源、宗門閉山或覆滅時自動離宗。**所有數值是初始猜測，實作時用 `npm run sim` 佐證。**

### 29.1 目標與界線

- 讓玩家在每一世多一條可選的人生路線：到宗門山門求入宗，在宗內晉升，辦差事，遇見同門；也可以不入，維持現在的散修玩法。
- **解除第 15 節的限制**：宗門（可加入）、有限的同門。
- **仍不做**：戰鬥與打鬥數值、師徒（不拜師、不傳功法）、陣營對立（入宗不使他宗成為敵人）、宗門之間的戰爭、跨世的人物。
- 同門只活在這一世：不跨世、沒有好感度或關係數值、玩家不能與他們互動，只出現在事件文字裡。這是對「NPC 關係」的最小例外。
- 世界觀：宗門文字一律用 `{guard}` 等名稱欄位，不寫死名稱；不得洩漏 `docs/WORLD.md` 第 14.3 節的真相。`docs/WORLD.md` 第 11 節「避免：加入門派」同步改為「仍避免拜師、收徒」。

### 29.2 入宗與離宗

- **條件**：練氣三層以上；人在該宗山門（用 M22 的旅行抵達）；宗門狀態為興盛、尋常或衰微（閉山不收、覆滅無人）。每世最多入一個宗門。
- **試煉**：成功率 = 基礎 + 悟性 × 每點 + 根骨 × 每點，靈根另有加成。大宗基礎低（約 25%）、門派高（約 50%），興盛 +、衰微 −。**每個宗門每世只能試一次**，失敗就記入 `sectsTried`，這一世不能再試。
- **離宗**：玩家可隨時主動離開，失去身分與貢獻，這一世不能再入同一宗（同樣記入 `sectsTried`）。
- **世局連動**：宗門閉山或覆滅時自動離宗，日誌寫一則，並加旗標 `sect_collapse`，讓事件可以接。宗門轉衰微時，加成依第 29.5 節降低。

### 29.3 位階與晉升

| 位階 | 條件（境界＋貢獻） | 備註 |
|---|---|---|
| 外門弟子 | 入宗即是 | 門派與大宗都有 |
| 內門弟子 | 築基＋貢獻 200 | |
| 執事 | 金丹＋貢獻 800 | 門派最高到這裡 |
| 長老 | 元嬰＋貢獻 2500 | 只有大宗 |

- 晉升由玩家按鈕決定（條件滿足才亮），確定性，沒有成功率。
- 貢獻只用於晉升，不能花掉；離宗歸零。

### 29.4 差事與任務

- **新日常安排「宗門差事」**（入宗後才開放）：修為 ×0.4，事件頻率 ×1.5 且偏向宗門事件，每月得貢獻（依位階 1–4），沒有採藥的靈石收入。
- **宗門事件即任務**：事件條件新增 `sect`（是否在宗、最低位階）；效果新增 `contribution`（加減貢獻）。新增事件只改 JSON，寫在 `src/data/events/sect.json`（M27，ChatGPT）。

### 29.5 好處

- **修煉加成** = 位階加成 × 宗門規模 × 興衰。位階：外門 +6%、內門 +12%、執事 +18%、長老 +25%；規模：大宗 ×1.0、門派 ×0.7；興衰：興盛 ×1.2、尋常 ×1.0、衰微 ×0.6。
- **月例**：入宗滿一年起每年發一次靈石（外門 2、內門 4、執事 8、長老 16，乘上規模與興衰，四捨五入），與日常安排的收入分開計。**原草案是每月 1／3／10／30，sim 證明太強**，見 29.12。
- **庫房**：入宗者買聚氣丹與築基丹打九折（延壽丹不折，保持每世上限的意義）。
- 數值放 `src/data/sects.json`（新檔），不散落在邏輯裡。

### 29.6 同門

- 新增事件欄位 `{peer}`、`{steward}`、`{elder}`，只在宗門事件允許；載入時檢查。

讓築基以上的大境界突破有「過程」：成功率不變，但玩家能在過程中做準備與選擇；把「按一下、出結果」變成一段短暫、有張力、可暫停的場面。

### 31.2 設計

- **哪些突破有天劫**：築基→金丹（3 道）、金丹→元嬰（5 道）、元嬰→化神（7 道）。練氣→築基沒有，維持新手簡單。劫波數寫在 `realms.json` 的 `breakthroughRule.tribulation.waves`，沒寫就是沒有天劫（等於現在的一鍵）。
- **成功率不變**：整個天劫的成功率等於現有的突破成功率 `rate`（悟性、神光、凝神、丹藥照舊）。每一道的基礎成功率是 `rate ^ (1 / 劫波數)`，連乘等於 `rate`。**不做準備時總成功率與現在完全相同，只是分成幾次抽。**
- **每一道的選擇**（時間暫停，介面一段一段呈現）：
  - 硬抗：不加不減（預設，自動抉擇也選這個）。
  - 運功護體：成功率加心性 × 1%（上限 +8%），代價是這一道若失敗，額外損失 5% 修為。
  - 祭出避雷符：消耗一張符籙，這一道成功率 +15%。符籙由 M29 煉製或坊市購買（新物品）。
  - 法寶護身：M30 之後，持有護身法寶可再加成。
- **失敗**：任何一道失敗即突破失敗，損失修為與現在相同（`30% − 心性 × 2% − 道心`），**不致死**，可再試。日誌寫第幾道失敗。
- **成功**：全部劫波通過才進入下一境界；日誌一則「度過天劫」，不重複寫突破成功。
- **離線**：天劫需要玩家在場，離線不會發生（突破本來就是手動）。
- **文字**：每道劫波一句（雷、風、火、心魔四種意象循環），寫在 `src/data/tribulation.json`，由 ChatGPT 寫內容。語氣肅穆，不吐槽（依第 17 節重場面規則）。

### 31.3 資料與存檔

- `realms.json` 的 `breakthroughRule` 新增 `tribulation?: { waves: number }`。
- `GameState` 新增 `tribulation: { wave: number; waves: number; rate: number; prepared: string[] } | null`；載入時檢查波數範圍。存檔升版。
- 新增 `src/data/tribulation.json`：劫波意象與每道的日誌句。

### 31.4 sim 與驗收

- 既有五種策略不選任何準備：輸出逐字不變。**注意**：把一次抽分成 N 次會改變 `rngSeed` 的消耗，造成與現有輸出不同。實作時要讓不做準備時只抽一次（以劫波數倍的單一亂數換算各道結果），或接受「亂數序列改變、統計分布不變」並重新建立基準，後者需經使用者同意。
- 新增 `tribulation` 策略：每道都用護體與符籙，量測金丹與元嬰的成功率提升幅度，目標是做足準備後成功率比不準備高約 1.3–1.6 倍，但不超過 95%。
- 驗收：天劫面板可操作、時間暫停、失敗不致死；`verify` 全過；五種策略輸出不變；瀏覽器實際完成一次築基→金丹天劫。

### 31.5 風險

- 亂數序列問題（見 31.4）是最大的技術風險，需先做一個小原型驗證。
- 符籙價格太低會讓天劫失去張力，太高則玩家不買；由 sim 與經濟校正。
- 遊戲內不稱「渡劫」（那是不可達的境界），只稱「雷劫」、「劫雲」，避免與 `docs/WORLD.md` 第 13.1 節混淆。

## 32. M29：材料與煉丹（草案，待審）

### 32.1 目標

讓靈石與時間有第二個出口，讓採藥、歷練、走訪渡口的收穫更有差異，並提供一條不靠運氣買丹的穩定路線。

### 32.2 設計

- **材料**：`items.json` 新增 `kind: "material"` 的物品（靈草、靈砂、妖丹、符紙各一種起步）。材料不能直接服用，只用來煉製。
- **來源**：現有日常安排的 `finds` 欄位已支援拾得物品，直接加入：採藥得靈草，外出歷練得靈砂與妖丹（低機率），走訪渡口得符紙。**採藥的 3 靈石／月維持不變**，材料是額外掉落，所以現有路線不受影響。
- **煉丹**：
  - 新日常安排「閉關煉丹」（`alchemy`，練氣起）：修為 ×0.3，事件頻率 ×0.7。每月消耗丹方所需材料的一份，累積滿「所需月數」後依成功率出丹；失敗損失一部分材料。
  - 丹方在 `src/data/recipes.json`：`{ id, output, inputs, months, baseRate, realmMin }`。成功率等於基礎加悟性 × 1%（上限 95%）。
  - 起步丹方：聚氣丹（靈草 × 4、2 個月）、護心丹（新：突破失敗損失 −10%，靈草 × 3、靈砂 × 1、3 個月）、避雷符（新：天劫一道 +15%，符紙 × 2、靈砂 × 1、2 個月）。築基丹與延壽丹不可煉，仍只能買（保持既有的價格錨點與每世上限）。
- **新物品效果**：`effect.kind` 新增 `failLossRelief`（護心丹）、`tribulationWard`（避雷符）。
- **丹毒**：護心丹與避雷符沒有丹毒；聚氣丹的丹毒計數照舊（煉出來的聚氣丹也算）。

### 32.3 資料與存檔

- 新增 `src/data/recipes.json`；`items.json` 加材料與新物品；`schedules.json` 加 `alchemy`。
- `GameState` 新增 `alchemy: { recipeId: string; progress: number } | null`；背包的材料用現有 `items`。存檔升版。
- 背包與坊市的介面要分「材料」「丹藥」「符籙」。

### 32.4 sim 與驗收

- 既有五種策略逐字不變。**注意**：在 `finds` 加材料會改變拾得物品的亂數消耗，要確認材料掉落用獨立的抽取序列，或接受基準重建（見 31.4 的同樣問題）。
- 新增 `alchemy` 策略：採藥攢材料、閉關煉聚氣丹。量測它的首次金丹中位數，不得低於第 7 世。
- 驗收：煉製過程可中斷與恢復；材料不夠時安排自動停止並提示；`verify` 全過。

### 32.5 風險

- 聚氣丹可自煉會讓「錢」這條槓桿鬆動，是最大的節奏風險；若 sim 顯示過快，降低靈草掉落率或拉長月數。
- 材料與丹方的種類容易膨脹；起步只做這 3 個丹方，其餘等第一輪量測之後再加。

## 33. M30：煉器與法寶（草案，待審）

### 33.1 目標

給玩家一個可累積的個人資產，並讓輪迴有傳承：每一世的成果能留下一件東西。

### 33.2 設計

- **法寶**：`items.json` 的 `kind: "artifact"`，有 `slot`（`weapon` 法器、`ward` 護身各一格）、`tier`（1–3）、`bonus`（修煉加成、突破失敗減免、天劫加成其中一至兩項，數值小，上限約 +12% 修煉）。
- **煉器**：在坊市花靈石與材料煉製（即時完成，不佔安排）。煉器配方也放在 `recipes.json`（`kind: "forge"`）；成功率與品階由悟性與材料決定。
- **裝備**：每格最多一件，隨時可換。死亡時法寶隨身消失。
- **傳承（輪迴連動）**：新增輪迴天賦「本命」（上限 3 級）：第 N 級讓你在轉世時保留 N 件法寶。這給法寶與道韻一個長期的連動，也是輪迴主題的具體呈現。
- **範圍**：沒有戰鬥，法寶只提供被動加成，不做攻擊力與防禦力。
- **世界觀**：`docs/WORLD.md` 第 11 節「避免」裡有「神兵」，此節改為「避免有名有姓的神兵與上古傳說」。

### 33.3 資料與存檔

- `GameState` 新增 `equipment: Record<"weapon" | "ward", string | null>`；`meta` 新增保留的法寶清單。存檔升版。
- `items.json` 新增 `kind`、`slot`、`tier`、`bonus`；載入時檢查格式。

### 33.4 sim 與驗收

- 既有策略不使用法寶：逐字不變。新增 `forge` 策略：量測有裝備時的首次金丹中位數，不得低於第 7 世。
- 驗收：可裝備、卸下、傳承；轉世保留正確的件數；`verify` 全過。

### 33.5 風險

- 法寶加成與心法、宗門加成疊加後可能過強：**所有修煉加成合計上限**（建議 +60%）寫入 `config.json`，超過的部分不計。
- 傳承讓玩家逐世強化，會壓縮第 13 節的世數目標；本命天賦的價格要用 sim 調整。

## 34. M32：前期體驗（草案，待審）

### 34.1 問題

- 第一世約 22 分鐘，平均止步練氣 6.5 層，**要到練氣九層才看得到突破鈕**，第一世見到築基約 1.8%。前 3–4 世幾乎只在練氣，缺少短期目標與回饋。
- 第 13 節的總目標（首次築基第 3–5 世、首次金丹第 8–12 世）目前都達成，所以問題不在總長度，而在前期缺少看得到的進展與選擇。

### 34.2 設計方向（不動總目標）

1. **看見突破鈕**：新增指標「第一世見到突破鈕（練氣九層圓滿）的比例」，目標至少 30%。做法：把練氣前幾層的需求放緩增長（`growth` 與 `base` 的微調），同時以築基的需求或成功率補償，使首次築基中位數仍在第 3–5 世。**具體數字由 sim 決定。**
2. **開場引路事件**（固定、不隨機）：第一世的前 3 年必出一則事件，送兩顆聚氣丹並說明安排與瓶頸的關係；寫在 `events/` 的新檔，由 ChatGPT 撰寫。
3. **短期里程碑日誌**：練氣三層、六層、九層各一則帶吐槽的鼓勵句（寫在 `text.json`）。
4. **第二世起的進步感**：回顧「與上一世的差別」已存在（階段 4）；補一行「這一世比上一世快了 N 年到達練氣 N 層」。
5. **介面提示**（ChatGPT）：狀態卡在練氣階段顯示「距離突破還差 N 層」。

### 34.3 驗收與風險

- 重跑第 13 節全部指標，更新第 13.1 節的結果表；`herb`、`wander` 回歸檢查仍要通過。
- 動前期數值會讓所有現有 sim 基準改變，所以 M32 排最前面，之後的里程碑都以新基準為對照。
- **需要使用者決定**：「第一世見到突破鈕至少 30%」這個目標是否合適。

## 35. M31：心法（草案，待審）

### 35.1 目標

讓每一世有「走哪條路」的身分感，而不是只有靈根倍率差異；用簡化的心法取代完整的功法樹。

### 35.2 設計

- **每世開局在擲骰畫面選一個心法**（可看見但不可中途更換）。預設是「無相訣」（所有效果為零，等於現在的玩法），所以不選時與現況相同。
- **心法清單**（`src/data/methods.json`，起步 4 個）：

| 心法 | 效果 | 取捨 |
|---|---|---|
| 無相訣 | 無 | 預設，對照基準 |
| 穩進訣 | 突破失敗損失 −6%；天劫護體多 +3% | 修煉速度 −4% |
| 疾行訣 | 修煉速度 +6% | 事件頻率 −15%，殘卷與機緣變少 |
| 遊塵訣 | 事件頻率 +20%，殘卷掉落 +20% | 修煉速度 −5% |

- **解鎖**：無相訣預設有；其餘三個依殘卷數解鎖（殘卷錄集到 4、8、12 份），把殘卷收集與玩法連動。
- **效果範圍**：只用既有的數值欄位（修煉倍率、事件頻率倍率、失敗損失、殘卷抽取權重、天劫加成），不新增戰鬥或技能。
- **世界觀**：心法是「吐納法門」，不是功法傳承；`docs/WORLD.md` 第 11 節的「功法」避免條目改為「避免具名功法與可修煉的招式」。

### 35.3 資料與存檔

- `GameState` 新增 `methodId: string`；`meta` 不新增（解鎖由殘卷數推出）。存檔升版。
- `src/data/methods.json`：`{ id, name, desc, effects, unlock: { fragments: number } }`，載入時檢查。

### 35.4 sim 與驗收

- 既有策略預設無相訣：逐字不變。新增 `method:穩進`、`method:疾行`、`method:遊塵` 三種策略：各自量測首次金丹與通關時間，**任一心法都不得讓首次金丹中位數低於第 7 世**，也不得比無相訣慢超過 2 世（避免有一個陷阱選項）。
- 驗收：擲骰畫面可選、未解鎖時有條件說明；`verify` 全過。

### 35.5 風險

- 遊塵訣會增加殘卷數，可能打亂第 18.7 節殘卷節奏（集滿 14 份中位數第 10–14 世），要一併檢查。
- 與宗門、法寶的修煉加成疊加，見 33.5 的合計上限。

## 36. 這一批的整體風險與審查清單

- **亂數序列**：天劫與材料掉落都可能改變現有 sim 的亂數消耗。實作前先用小原型確認是否能做到「不使用時逐字不變」；做不到時要先經使用者同意重建基準。
- **加成疊加**：宗門（最高 +25%）、法寶（最高 +12%）、心法（±6%）、輪迴天賦（宿慧等）會相乘；合計上限要寫進設定，並加一個總體 sim 策略量測。
- **工作量**：五個里程碑的核心工作主要在 Claude；ChatGPT 負責介面與文字內容。建議每完成一個里程碑就用 sim 驗收並合併，不要累積。
- **使用者要審的決定**：
  1. 第 15 節新增例外：心法（簡化功法）、煉丹與煉器（材料、丹方、法寶）、天劫。
  2. M32 的目標指標與是否接受第 13 節基準被更新。
  3. 天劫是否接受「亂數序列可能改變」的前提（31.4）。
  4. 本命天賦（輪迴傳承法寶）是否納入 M30。
